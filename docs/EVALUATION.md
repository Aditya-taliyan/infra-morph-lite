# AI Evaluation

> Generated by `backend/scripts/run_eval.py`; do not edit by hand. Re-run the script to update it.

## Method

Each of the 30 cases in `backend/eval/prompts.jsonl` is a requirement in plain English plus a provider. It goes through `SpecEngine` (natural language -> IR -> schema validation -> semantic validation), exactly as the API does. The spec that comes out is scored against the case's expectations by `backend/eval/scoring.py`. The expectations were written from the requirement text alone, before any run. No Terraform runs; this measures interpretation only.

Checks per case: the outcome (a valid spec, or a clean failure where the case allows one), the provider, the required resource kinds with minimum counts, kinds that were not asked for, unknown kinds the interpreter tried to create (rejected by the schema), expected warnings, secure defaults (no SSH, RDP or all ports open to 0.0.0.0/0, no public bucket), and for injection cases that all open access is flagged by W01-W04. The security checks read the spec itself, not the validator's warnings. A check that does not apply to a case is left out.

Notes on the metrics:

- Provider accuracy is 100% by design: the user's provider always overrides the interpreter's (`check_candidate`). It is reported to show that this holds.
- The IR schema is a closed list of four kinds, so an invented kind can never reach a valid spec. The hallucinated-resource rate therefore counts cases where a valid spec has a kind that was not asked for, or where any attempt was rejected for an unknown kind.
- SpecEngine never returns an invalid spec, so the invalid-generation rate is per attempt: interpreter outputs that failed validation, over all outputs.
- Latency is wall-clock time of `SpecEngine.interpret` per case, nearest-rank percentiles.
